## 1부. 만들면서 겪은 문제

서버에서 8개, 클라이언트에서 4개, 문제가 발생하기 전에 발견한 것이 1개다.

### 서버

#### 1. 소리는 나는데 전부 잡음이었다

- **증상**: 출력 게이지는 올라가고, 길이와 음량이 맞는 WAV가 나오는데 내용은 지지직거리는 잡음이었음. 가장 오래 걸린 문제.
- **원인**: 가중치를 `load_state_dict(..., strict=False)`로 읽고 있었음. `strict=False`는 이름이 안 맞는 가중치를 건너뛰는 옵션인데, 체크포인트 안의 이름이 지금 모델의 이름과 달라서 **가중치를 하나도 읽지 않았음.** 오류는 나지 않고 조용히 성공으로 처리됨. 모델은 무작위 숫자로 채워진 채로 돌아가고 있었음.
- **해결**: `strict=True`로 바꾸고, 이름이 안 맞으면 순서대로 짝을 지어 넣도록 고침. 실제로 무엇이 읽혔는지 확인할 수 있는 `/health` 주소를 추가함.
- **확인**: `/health`에서 핵심 모듈 7개(`predictor`, `decoder`, `text_encoder`, `prosodic_text_encoder`, `predictor_encoder`, `style_encoder`, `diffusion`)가 모두 읽힌 것으로 나옴.
- **남긴 것**: 조용히 넘어가면 안 됨. 틀렸으면 그 자리에서 멈춰야 함.

#### 2. 운율과 소리가 한 칸씩 어긋났다

- **원인**: 원본 추론 코드에는 디코더에 넣기 직전에 값을 한 프레임 옆으로 미는 처리가 있었음. 조건문 안에 들어 있어서 다른 디코더 전용인 줄 알고 뺐는데, 실제로는 무조건 적용되는 처리였음.
- **해결**: 다시 넣음.

#### 3. 글자대로 읽어서 발음이 어색했다

- **원인**: 모델은 "같이"를 "가치"로 바꾼 글로 학습했는데, "같이"를 그대로 입력으로 넣고 있었음.
- **해결**: 학습 때 사용한 것과 같은 발음 변환기(g2pk)를 입력 앞에 넣음. 변환기를 사용할 수 없는 환경이면 자음과 모음으로만 분해해서 넘어가게 함.

#### 4. 서버가 내 파일을 찾지 못했다

- **증상**: 설정에 `D:\voice.wav`를 적었는데 서버는 파일이 없다고 함.
- **원인**: 서버는 Docker 컨테이너 안에 있음. 컨테이너는 허용하는 경로를 직접 정해서 설정하지 않으면 내 PC의 다른 폴더를 볼 수 없음.
- **해결**: 경로를 보내는 대신 파일 내용을 통째로 보내도록 바꿈. 클라이언트가 파일을 읽어서 텍스트와 함께 올림. 매번 같은 파일을 분석하면 느리므로, 서버는 파일 내용의 해시를 열쇠로 삼아 분석 결과를 기억해 둠.

#### 5. RTX 5070에서 동작하지 않는다

- **원인**: 처음 사용한 Docker 이미지는 PyTorch 2.1, CUDA 11.8이었는데 이 조합은 RTX 50 시리즈와 호환되지 않음.
- **해결**: 베이스 이미지를 PyTorch 2.7, CUDA 12.8로 바꿈.

#### 6. 로그가 보이지 않았다

- **증상**: 컨테이너 안에서 `print`로 찍은 글이 화면에 안 나옴.
- **원인**: 출력이 버퍼에 쌓여 있다가 한참 뒤에 나오는 것이었음.
- **해결**: 환경 변수 `PYTHONUNBUFFERED=1`을 넣음. 이 값을 설정하면 모든 출력이 버퍼를 거치지 않고 즉시 콘솔로 전송됨. 1번에서 만든 `/health`도 여기서 쓸모가 있었음. 로그가 안 보여도 상태를 볼 수 있음.

#### 7. 켤 때마다 2.48GB를 다시 받았다

- **증상**: 모델 파일은 내 PC 폴더에 저장되게 해 두었는데도 컨테이너를 다시 만들 때마다 처음부터 내려받음.
- **원인**: 파일은 남아 있었음. 사라진 것은 "이 파일을 이미 받았다"는 기록이었음. 그 기록은 컨테이너 안에 있었고 컨테이너와 함께 지워졌음.
- **해결**: 기록에 기대지 않고 파일이 있는지, 크기가 1GB를 넘는지를 직접 확인해서 건너뛰도록 고침.

#### 8. 세 번에 한 번, 30초짜리 잡음이 나왔다

- **증상**: 한참 잘 사용하다가 발견함. 미리듣기를 누르면 가끔 잡음만 나오고, 다시 누르면 정상이었음. 잡음이 한번 나오기 시작하면 멈추지 않고 계속 나옴. 같은 요청을 60번 보내 보니 22번이 잡음이었고, 3.5초여야 할 음성이 7초에서 29초짜리 잡음으로 나왔음.
- **원인**: "표현력 강도" 설정이었음. 이 값이 1.0이 아니면 모델 안에서 스타일을 만드는 계산이 무작위로 발산함. 정상일 때 2 안팎이어야 할 숫자가 수천, 수백만까지 튀고, 그 값이 그대로 다음 단계로 넘어가면 문장 길이 예측이 망가져서 긴 잡음이 됨. 설정은 1.1로 살짝 올려 두었을 뿐이었음.

  | 표현력 강도 | 잡음이 나온 횟수 |
  |---|---|
  | 1.0 | 240번 중 0번 |
  | 1.1 | 60번 중 22번 |
  | 1.5 | 50번 중 38번 |
  | 3.0 | 50번 중 45번 |

- **해결**: 서버는 스타일 값을 만든 직후에 정상 범위인지 검사하고, 벗어나면 다시 만듦. 계속 실패하면 1.0으로 만듦. 클라이언트에서는 슬라이더를 없애고 1.0으로 고정함. 이 모델에서는 올려도 효과가 없는 값이었음.
- **확인**: 고친 뒤에 400번을 보냈고 잡음은 한 번도 나오지 않았음.

### 클라이언트

#### 9. 볼륨 슬라이더가 먹지 않았다

- **증상**: 볼륨을 끝까지 내려도 프로그램으로 나가는 소리 크기가 그대로였음.
- **원인**: 윈도우의 볼륨 조절 기능은 "장치"에게 소리를 줄이라고 요청하는 방식인데, VB-Cable은 그 요청을 듣지 않음. 서버는 서버대로 소리를 항상 최대 크기에 맞춰서 보내고 있었음.
- **해결**: 장치에 요청하지 않고, 재생하기 전에 소리 데이터의 숫자를 직접 줄이도록 바꿈. 어떤 장치든 작동함.

#### 10. 미리듣기가 출력으로 나갈 뻔했다

- **증상**: 설정 창의 미리듣기는 내 스피커로만 들려야 하는데, 출력 장치로 나갈 수 있는 상태였음.
- **원인**: 장치 이름을 비워서 넘기면 기본 장치로 재생된다고 생각했지만, 코드는 이름이 "포함된" 장치를 찾고 있었음. 빈 문자열은 모든 이름에 포함되므로 항상 목록의 첫 번째 장치가 선택됨. 첫 번째가 VB-Cable이면 미리듣기가 그대로 출력됨.
- **해결**: 이름이 비어 있으면 찾지 않고 기본 장치를 사용하도록 고침.

#### 11. 단축키 설정 칸에서 단축키가 눌리지 않았다

- **증상**: 단축키를 바꾸려고 설정 칸을 누르고 Ctrl+T를 누르면, 칸에는 아무것도 안 들어오고 입력창만 열렸다 닫혔음.
- **원인**: 전역 단축키는 윈도우가 먼저 가로챔. 등록된 조합은 어느 프로그램의 입력 칸에도 전달되지 않고, 내 프로그램의 설정 칸도 예외가 아님.
- **해결**: 설정 칸을 누르는 순간 단축키를 잠깐 끄고, 칸을 벗어나면 다시 켜도록 함. 조합을 누르면 그 자리에서 등록이 되는지 시험해 보고, 다른 프로그램이 사용하는 조합이면 바로 알려 줌. 전에는 저장을 눌러야 실패를 알 수 있었음.
- **함께 고친 것**: Win 키가 인식되지 않는 문제. WPF가 Win 키를 조합 키로 알려 주지 않아서, 키가 눌렸는지 프로그램이 직접 확인하도록 함.

#### 12. 폴더를 옮기면 목소리 파일을 잃어버렸다

- **원인**: 목소리 파일 경로를 `C:\...\voice\voice.opus`처럼 전체 경로로 저장하고 있었음. 프로그램 폴더를 다른 드라이브로 옮기면 설정에는 예전 경로가 남음.
- **해결**: 프로그램 폴더 안에 있는 파일은 `voice\voice.opus`처럼 상대 경로로 저장하도록 바꿈. 폴더 밖의 파일만 전체 경로로 저장함. 파일이 없을 때는 "목소리 오디오 파일을 찾을 수 없습니다"로 시작하는 안내가 뜸.
- **함께 고친 것**: 지원하지 않는 확장자는 등록되지 않게 막음. wav, flac, ogg, opus, mp3, m4a 여섯 가지만 받음.

### 문제가 발생하기 전에 발견한 것

#### 13. 같은 공유기를 쓰는 누구나 내 GPU를 쓸 수 있었다

- **발견**: 코드를 다시 읽다가 발견함. 서버 포트가 모든 네트워크에 열려 있었고 인증은 없었음. 요청 값에도 상한이 없어서, 문장 길이나 스타일을 다듬는 횟수(diffusion steps)에 큰 숫자를 넣으면 서버가 멈출 수 있었음.
- **해결**: 포트를 내 PC에서만 접속되도록 설정함. 요청 값에는 범위를 걸었음. 텍스트는 2,000자, 다듬는 횟수는 100까지임.

### 문제는 아니지만 고친 것들

| 한 일 | 이유 |
|---|---|
| 음색, 억양 슬라이더를 설정 창에 노출 | 기본값이 다양한 표현 쪽에 맞춰져 있어서 참조 목소리를 덜 따라갔음 |
| 말하는 속도 조절 | 상황에 따라 조절해서 말해야 할 때가 있음 |
| 참조 음성 길이 제한 (3초 이상, 15초 초과는 구간 지정) | 너무 짧으면 특징을 못 잡고, 너무 길면 특징이 평균이 되어 흐려짐 |
| mp3, m4a 등 형식 지원 | 갖고 있는 파일이 wav가 아닌 경우가 많음 |
| 송출시 듣기 | 가상 케이블로 내보내면 정작 나는 안 들림. 체크하면 내 스피커로도 같이 들림 |
| 재생 중단 단축키 (Ctrl+Alt+X) | 잘못 보낸 문장을 끊을 방법이 없었음 |
| 단축키를 누르고 있으면 창이 깜빡이던 것 | 키 반복 입력을 무시하도록 함 |

### 마우스 버튼은 사용하지 않는다

단축키로 마우스 옆 버튼을 사용하는 것을 검토했지만 넣지 않았음.

- 마우스 버튼을 전역으로 감지하는 대표적인 방법은 저수준 마우스 훅(low-level mouse hook)인데, PC의 모든 마우스 입력을 프로그램이 중간에서 탐지하는 방식임.
- 프로그램이 잠깐이라도 멈추면 마우스 전체가 버벅일 수 있고, 입력을 가로채는 방식이다 보니 Windows Defender 같은 백신 프로그램이 키로거로 의심할 여지도 있음.
- 안티치트가 이것을 어떻게 판단하는지는 공개되어 있지 않음. 걸린다는 근거를 찾은 것은 아니지만, 주로 하는 게임이 전부 안티치트가 작동하는 게임이라 확인되지 않은 위험을 감수하지 않기로 함.
- 키보드 단축키는 윈도우가 정식으로 제공하는 기능(`RegisterHotKey`)을 사용함. 다른 프로그램의 입력을 들여다보지 않고, 지정한 조합이 눌렸을 때만 윈도우가 알려 주는 방식임.

## 2부. 해결하지 못한 문제: 내 목소리가 아니었다

### 증상

- 참조 음성을 넣고 들어 보면 톤과 분위기는 비슷하지만, 같은 사람으로 들리지는 않음. 비슷한 톤의 다른 사람임.
- 쉰 듯한 기계음이 섞여 있음.
- 음색 슬라이더와 억양 슬라이더를 참조 쪽으로 끝까지 당겨도 "같다"까지는 아니었음.

### 왜 안 닮는가

- 참조 음성 10초를 넣으면 모델은 그것을 숫자 256개(스타일 벡터)로 줄임. 음색을 담는 128개와 운율을 담는 128개임. 참조 음성이 10초든 15초든 모델에 전달되는 것은 이 256개가 전부임.
- 이 256개는 "학습할 때 들어 본 목소리들 사이의 어느 한 지점"을 가리킴. 들어 본 적 없는 목소리를 넣으면, 들어 본 목소리 중에서 가장 가까운 것을 선택함.
- 모델을 만든 사람들도 논문에 이 점을 한계로 적어 두었음. 원본 저장소가 권하는 방법도 참조 음성 몇 초가 아니라, 그 사람의 녹음 1시간 정도로 모델을 추가 학습시키는 것이었음.
- 선택한 체크포인트에도 아쉬운 점이 있었음. 학습에 사용한 화자가 몇 명인지 공개되어 있지 않고, Fork를 만든 사람이 README에 "원본만큼의 음질이 안 나올 수 있다"고 적어 두었음.

### 쉰 소리는 어디서 오는가

- **코드 확인**: 서버의 추론 코드를 원본 저장소의 참조 코드와 한 줄씩 비교했고, 같았음. 체크포인트와 함께 공개된 학습 데이터 목록에서 한국어가 발음 변환을 거친 뒤 자음과 모음으로 분해한 형태인 것도 확인했고, 서버가 하는 방식과 같았음. 코드에는 문제가 없었음.
- **설정 측정**: 목소리가 얼마나 맑은지를 나타내는 값(HNR)으로 측정함. 높으면 맑고 낮으면 쉰 소리에 가까움.

  | 조건 | 맑은 정도 |
  |---|---|
  | 속도 0.8 | 10.2 dB |
  | 속도 1.0 | 8.9 dB |
  | 속도 1.4 | 7.6 dB |
  | 사용하던 설정 (속도 1.4) | 7.3 dB |
  | 음색, 억양 슬라이더를 끝까지 | 9.4 dB |
  | 다듬는 횟수(diffusion steps) 5 -> 30 | 8.9 -> 9.4 dB |

- **원인 1, 속도**: 속도를 1.4배로 올려 두고 있었음. 이 모델은 음소의 길이를 억지로 줄이는 방식으로 속도를 올리기 때문에 그만큼 소리가 거칠어짐.
- **원인 2, 참조 음성**: 합성 결과는 참조 원본의 맑은 정도를 거의 그대로 따라감. 한 참조 음성은 원본 8.5 dB에 결과 9.2 dB, 다른 참조 음성은 원본 11.3 dB에 결과 14.8 dB였음.
- **남은 부분**: 속도를 내리고 맑은 참조 음성을 사용하면 개선되지만 없어지지는 않음. 이 Fork가 사용하는 디코더의 질감이고, 설정으로는 해결할 수 없었음.

### 검토한 방법

| 방법 | 결과 |
|---|---|
| 내 목소리로 추가 학습 | 포기. 분 단위의 녹음이 필요함 |
| 지금 모델 뒤에 음성 변환(RVC) 연결 | 포기. 학습에 10분 정도의 녹음이 필요함 |
| 참조 음성 몇 초만으로 더 잘 닮게 만드는 다른 모델 | 시도함 |

마이크를 사용할 수 없어서 시작한 프로젝트이다 보니 10분짜리 녹음을 새로 만들 수가 없었고, 사용할 수 있는 것은 10초 남짓의 깨끗한 음성뿐이었음. 그래서 10초로 가능한 두 가지만 남겼음.

| 이름 | 하는 일 | 필요한 음성 |
|---|---|---|
| OpenVoice v2 | TTS 결과의 음색을 참조 음성에 맞게 바꿈. 학습이 필요 없음 | 몇 초 |
| GPT-SoVITS (v2ProPlus) | TTS 모델 자체를 바꿈. 참조 음성을 숫자로 줄이지 않고, 직접 이어 붙여서 사용함 | 3\~10초 |

### 모델 2개를 연결하면서 생긴 일

구조는 `TTS Overlay -> TTS Server -> (StyleTTS2 또는 GPT-SoVITS) -> (선택) OpenVoice -> WAV`로 바꿨음. 기존 서버가 중계 역할을 하고, 두 모델은 각각 별도의 컨테이너로 가동함. 세 프로그램이 요구하는 라이브러리 버전이 서로 달라서 한 컨테이너에 넣을 수 없었기 때문임.

- GPT-SoVITS는 공식 Docker 이미지가 있었음. 내려받는 데 11GB, 풀고 나면 29GB임.
- GPT-SoVITS는 참조 음성을 파일 경로로만 받음. 4번 문제와 같은 상황이라, 두 컨테이너가 같이 보는 폴더를 하나 만들어서 해결함.
- GPT-SoVITS는 참조 음성이 3초에서 10초 사이여야 하고, 벗어나면 거부함. 서버가 잘라서 넘기도록 함.
- GPT-SoVITS는 참조 음성에서 말하는 내용을 글로 적어 주면 결과가 좋아진다고 해서, 설정 창에 대본 칸을 추가함.
- OpenVoice는 결과 음성에 들리지 않는 워터마크(AI가 만든 음성이라는 표식)를 넣음. 이것을 켜고 끄는 옵션이 라이브러리에 있었지만, 실제로 넣으면 오류가 났음. 옵션 없이 만든 뒤에 따로 설정하는 방법으로 우회했고, 기본값은 켜 둔 상태로 둠.

둘 다 RTX 5070에서 동작했음.

### 측정

- 문장 12개 (짧은 문장 4개, 중간 문장 4개, 긴 문장 4개)
- 참조 음성 3개. 공개 음성 데이터셋인 [Zeroth-Korean](https://huggingface.co/datasets/Bingsu/zeroth-korean)(CC BY 4.0)에서 2개, 테스트용으로 구한 음성 1개
- 설정 5가지, 각 2번씩. 합쳐서 360개

| 항목 | 측정 방법 |
|---|---|
| 지연 | 요청을 보내고 음성을 다 받을 때까지의 시간 |
| 글자 오류율 | 합성한 음성을 음성 인식(Whisper)으로 받아써서 원래 문장과 비교 |
| 화자 유사도 | 화자를 구분하는 모델로 참조 음성과 비교한 값. 1에 가까울수록 같은 사람 |
| GPU 메모리 | 컨테이너를 하나씩 가동하면서 늘어난 양 |

**결과**

| 설정 | 지연 | 글자 오류율 | 화자 유사도 |
|---|---|---|---|
| StyleTTS2 (원래 모델) | 0.13초 | 1.0% | 0.944 |
| StyleTTS2 + OpenVoice | 0.22초 | 1.2% | 0.918 |
| GPT-SoVITS, 대본 없음 | 0.67초 | 7.3% | 0.925 |
| GPT-SoVITS, 대본 있음 | 0.79초 | 2.1% | 0.918 |
| GPT-SoVITS + OpenVoice | 0.84초 | 10.7% | 0.890 |

GPU 메모리는 StyleTTS2가 약 1.4GB, OpenVoice가 약 0.7GB, GPT-SoVITS가 약 1.6GB였음. 3개를 다 가동해도 3.8GB임.

**닮은 정도는 차이가 없었음**

- 기대한 결과는 "느려지는 대신 닮아진다"였지만 그렇게 나오지 않았음.
- 화자 유사도는 원래 모델이 0.944로 가장 높았지만, 이 숫자로 원래 모델이 더 낫다고 말할 수는 없음. 설정 사이의 차이가 0.02에서 0.03인데, 같은 설정 안에서 문장마다 달라지는 폭이 0.03에서 0.05였음.
- 기준값: 같은 사람의 다른 구간은 0.976, 서로 다른 사람은 가장 멀었던 쌍이 0.486, 가장 가까웠던 쌍이 0.860.
- 합성한 음성들은 0.89에서 0.94 사이에 모여 있음. 10초짜리 참조 음성으로는 어느 모델을 사용해도 비슷한 곳에서 막힘.

**짧은 문장이 망가졌음**

| 설정 | 짧은 문장 | 중간 문장 | 긴 문장 |
|---|---|---|---|
| StyleTTS2 | 0.8% | 2.3% | 0.0% |
| StyleTTS2 + OpenVoice | 0.8% | 2.8% | 0.0% |
| GPT-SoVITS, 대본 없음 | 14.5% | 4.0% | 3.4% |
| GPT-SoVITS, 대본 있음 | 2.5% | 2.3% | 1.5% |
| GPT-SoVITS + OpenVoice | 19.4% | 9.7% | 2.9% |

| 입력한 문장 | 받아쓴 결과 | 설정 |
|---|---|---|
| 네, 알겠습니다. | 네, 아이디스입니다. | GPT-SoVITS, 대본 없음 |
| 지금 바로 갈게요. | 심지어 닫아야 되요 | GPT-SoVITS + OpenVoice |
| 그건 좀 어려울 것 같아요. | 원하고 파타워. | GPT-SoVITS + OpenVoice |

- 소통할 때 사용하는 말은 거의 다 짧음. 짧은 문장이 망가지면 사용할 수가 없음.
- 대본을 적어 주면 GPT-SoVITS의 오류율은 2%대로 내려가지만, 참조 음성을 바꿀 때마다 그 음성에서 뭐라고 말하는지 받아 적어야 하는 것 자체가 번거로웠음.

**정리**

- 속도: 원래 모델이 5배에서 6배 빠름
- 정확도: 원래 모델이 가장 좋음
- 닮은 정도: 측정으로는 구분되지 않았음
- 맑은 정도: GPT-SoVITS가 조금 나음 (11.6 dB 대 10.5 dB)

### 다시 되돌렸다

- 숫자만 보고 결정한 것은 아니고, 설정을 바꿔 가며 직접 들어 봤음. 사용할 수 없겠다는 생각이 먼저 들었음.
- 느려진 것은 감수할 수 있었음. 문제는 느려진 만큼 얻은 것이 없다는 점이었음. 닮지도 않았고, 짧은 말은 이상하게 나왔음.
- 두 모델과 측정 코드, 모델 선택 화면을 전부 제거함. 내려받은 이미지와 모델 파일도 지움. 원래 모델 1개로 돌아옴.
- 제거하기 전에 현재 상태를 통째로 복사해 두었고, 제거한 뒤에는 서버를 다시 가동해서 합성이 되는지 확인함. 측정 결과 표는 문서에 남겼음. 다음에 같은 시도를 또 하지 않기 위해서임.

### 얻은 것

- 안 되는 것을 "안 되는 것 같다"에서 "측정해 보니 안 된다"로 바꿨음. 측정하기 전에는 다른 모델로 바꾸면 될 것 같다는 생각이 계속 남아 있었는데, 지금은 10초짜리 참조 음성으로는 어느 쪽도 비슷하다는 것을 앎.
- 조용히 넘어가는 것을 믿지 않게 됐음. `strict=False`도, 표현력 강도 1.1도, 빈 문자열이 첫 번째 장치로 선택된 것도 전부 오류 없이 넘어간 것들이었음.

## 한계

- **10초짜리 참조 음성으로는 본인 목소리가 나오지 않는다.** 세 가지 방식 모두 "비슷한 톤의 다른 사람" 근처에서 멈췄음
- **녹음을 새로 만들 수 없으면 추가 학습을 할 수 없다.** 가장 확실한 방법이 이 프로젝트의 시작 계기와 충돌함
- **화자 유사도 숫자는 귀를 대신하지 못한다.** 음색의 전체적인 특징만 봄. 말투나 억양 습관, 기계음 같은 질감은 잡지 못함
- **기계음이 남아 있다.** 속도를 내리고 맑은 참조 음성을 사용하면 줄어들지만 없어지지는 않음
- **모델 파일이 비상업용이다.** 코드는 MIT로 올리지만 모델은 직접 만든 것이 아니고, 사용 조건(CC BY-NC 4.0)이 따로 있음
- **인증이 없다.** 그래서 내 PC 안에서만 접속되도록 설정해 두었음. 다른 기기에서 사용하려면 VPN이나 인증을 따로 구성해야 함

## 앞으로 할 것

모델은 TTS Server 쪽만 교체하면 되는 구조임. TTS Overlay는 "텍스트를 보내면 WAV가 온다"는 것만 앎. 참조 음성 몇 초로 더 잘 닮게 만드는 모델이 나오면 그때 다시 측정해 볼 생각임.

- 자주 사용하는 말을 단축키에 넣어 두기. 대화에서 가장 느린 구간은 합성이 아니라 타이핑하는 시간임
- 합성 대기열. 지금은 소리가 나오는 동안 누른 Enter가 무시됨
- 서버를 가동했을 때 미리 한 번 합성해 두기. 첫 요청만 약 9초가 걸림
- 실행 파일 하나로 묶기

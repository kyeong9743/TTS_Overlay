## 1. 결론

- **현재 체크포인트의 제로샷으로는 본인 목소리가 나오기 어렵다.** 설정을 더 조정해서 해결될 문제가 아니라, 참조 음성을 128차원 벡터 두 개로 압축하는 구조와 학습 규모에서 오는 한계다. StyleTTS2 논문 저자들도 제로샷 화자 유사도를 한계로 직접 적었다.
- **목표가 "내 목소리와 최대한 같게"라면 녹음으로 파인튜닝하는 쪽이 맞다.** 다만 이 방법은 10\~60분 분량의 녹음과 대본이 있어야 하는데, 이 프로젝트에서는 녹음을 새로 만들 수 없어서 선택하지 못했다. 그래서 10초 안팎의 참조 음성 하나로 할 수 있는 방법만 남았다.
- **속도는 현재 모델이 이미 충분히 빠르다.** 첫 요청 이후에는 문장당 0.11 \~ 0.15초다. 모델을 바꾸면 속도는 대체로 느려진다.
- **조사 시점의 1순위 후보는 GPT-SoVITS였고, 실제로 연결해서 측정한 뒤 제거했다.** 10초 참조 음성만으로는 화자 유사도가 현재 모델보다 뚜렷하게 낫지 않았고 속도는 5 \~ 6배 느렸다. OpenVoice v2도 같은 결과였다. 현재 TTS 출력 뒤에 RVC를 연결하는 방법은 학습에 약 10분의 녹음이 필요해서 시도하지 못했다. 측정 수치는 맨 위의 후속 메모에 있다.
- **이 프로젝트의 차별점은 모델이 아니라 사용 흐름이다.** 모델은 공개된 것을 가져다 쓴 것이고 교체 가능하다. 이 프로젝트의 가치는 "마이크를 쓸 수 없는 사람이 타이핑으로 자기 목소리를 보이스챗에 내보내는 도구"라는 점이다.

## 3. 왜 내 목소리처럼 들리지 않는가

### 3.1 구조에서 오는 한계

이 모델이 참조 음성에서 가져가는 정보는 **128차원 벡터 두 개가 전부**이다. `style_encoder`가 음색을, `predictor_encoder`가 운율을 각각 한 벡터로 요약한다([server.py:96-102](../TTS_Server/server.py#L96-L102)). 12초짜리 참조를 넣어도 모델에 전달되는 것은 숫자 256개다.

이 벡터는 "학습 때 본 화자들이 이루는 공간 안의 한 점"이다. 본인 목소리가 그 공간 안에 잘 표현되지 않으면 가장 가까운 점, 즉 **비슷한 톤의 다른 사람 목소리**가 나온다. "톤과 분위기는 닮았는데 내 목소리는 아니다"라는 증상이 이 구조와 정확히 맞다. [판단]

최근의 대규모 모델들은 방식이 다르다. 참조 음성을 벡터 하나로 줄이지 않고 프롬프트로 그대로 이어 붙여, 음색의 세부와 발성 습관을 직접 참조한다. [조사]

### 3.2 논문이 밝힌 한계 [조사]

- StyleTTS2 논문은 VALL-E와 비교해 자연스러움은 높지만 화자 유사도는 낮다고 보고한다.
- 저자들이 "제로샷 화자 유사도는 추가 개선이 필요하다"고 한계 항목에 직접 적었다.
- 원본 저장소가 화자 적응을 위해 안내하는 방법은 제로샷이 아니라 **파인튜닝**이고, 권장 데이터는 약 1시간이다.

### 3.3 이 체크포인트 고유의 요인

- 화자 수가 공개되어 있지 않다. 총 시간은 많아도 화자 다양성이 낮으면 새로운 목소리에 대한 일반화가 떨어진다. [판단]
- 2단계 학습이 설정된 8에폭을 다 채우지 않은 6에폭 시점의 저장본이다. [실측]
- 디코더가 Vocos로 바뀌면서 음질 손실 가능성이 Fork README에 언급되어 있다. [조사]

### 3.4 현재 설정에서 더 해볼 수 있는 것

분석 시점의 설정은 이미 `alpha 0.15`, `beta 0.2`로 참조 쪽에 가깝게 맞춰져 있었다. 남은 조정 여지는 다음 정도다.

| 시도 | 기대 효과 |
|---|---|
| `alpha`, `beta`를 0으로 | diffusion 예측을 완전히 끄고 참조 벡터만 사용. 유사도는 이 모델이 낼 수 있는 최대치가 되지만 억양이 단조로워짐 |
| 참조 음성을 직접 녹음한 깨끗한 음성으로 교체 | 분석 시점의 참조 음성은 압축된 음원이었다. 압축 음원은 배경음과 압축 손실이 스타일 벡터를 흐린다. 조용한 곳에서 평소 말투로 10초가량 직접 녹음한 WAV가 더 낫다 |
| 참조 구간을 평소 말하는 톤으로 고르기 | 감정이 실린 구간보다 평범하게 말하는 구간이 안정적 |

이것으로 "조금 더 비슷하게"는 가능하지만 "같게"까지는 가지 못한다. 3.1의 한계는 설정으로 넘을 수 없다. [판단]

## 4. 대체 모델 후보

조건은 세 가지로 잡았다. 한국어 지원, 음성 복제(제로샷 또는 본인 녹음 파인튜닝), 12GB GPU에서 자체 호스팅 가능.

4번은 전부 **[조사]** 내용이다. 조사 시점에는 이 PC에서 실행해 본 모델이 없었다. 이후 GPT-SoVITS와 OpenVoice v2를 실행한 결과는 맨 위의 후속 메모에 있다.

### 4.1 조건을 충족하는 후보

| 모델 | 한국어 | 복제 방식 | 속도, 메모리 | 라이선스 (가중치) | 비고 |
|---|---|---|---|---|---|
| **GPT-SoVITS** (v2ProPlus 등) | 공식 | 제로샷 5초, 파인튜닝 1분\~ | RTF 0.028 (RTX 4060Ti) | MIT | 본인 음성 소량 파인튜닝에 특화. 전처리 WebUI와 API 서버 포함. PyTorch 2.7 / CUDA 12.8이 테스트 환경에 있음 |
| **Qwen3-TTS** Base (0.6B, 1.7B) | 공식 | 제로샷 3초, 공식 파인튜닝 스크립트 | 스트리밍 첫 소리 약 0.1 \~ 0.2초. 기본 구현은 실시간보다 느려 가속 Fork 필요 | Apache-2.0 | 한국어 유사도 수치가 공개된 유일한 후보 (SIM 약 0.80 \~ 0.82) |
| **VoxCPM2** | 공식 | 제로샷, LoRA 파인튜닝 5\~10분 분량 | 약 8GB, RTF 약 0.3 (RTX 4090) | Apache-2.0 | 스트리밍 API. 한국어 유사도 수치 없음 |
| **Fun-CosyVoice3** 0.5B | 공식 | 제로샷, 학습 스크립트 | 스트리밍 지연 150ms 수준 주장 | Apache-2.0 | 한국어 수치 없음 |
| **Fish Audio S2 Pro** | 지원 | 제로샷 10\~30초, 파인튜닝 | 모델이 커서 12GB에서 부담 가능성 | 비상업 연구 라이선스 | 품질은 유력하나 크기와 라이선스가 걸림 |
| **Chatterbox Multilingual** | 지원 | 제로샷 약 10초 | 미기재 | MIT | 출력에 워터마크 삽입 |
| **XTTS-v2** | 공식 | 제로샷 6초, 파인튜닝 | 스트리밍 가능 | 비상업 (CPML) | 개발사 종료, 커뮤니티 Fork로 유지. 세대가 오래됨 |
| **OpenVoice v2 + MeloTTS** | 지원 | 제로샷 음색 변환 | 가볍고 빠름 | MIT | 음색만 옮기고 억양은 베이스 화자 것 |
| **기존 TTS + RVC** | 언어 무관 | 본인 음성 약 10분 학습 | 추가 지연 0.1\~0.2초 수준 | MIT | TTS 출력을 본인 음색으로 변환하는 후처리 |

GPT-SoVITS는 최근 V5가 저장소에 올라왔다고 조사됐으나, 공개 직후라 한국어 품질과 메모리 요구량이 확인되지 않았다. 검증된 v2ProPlus로 먼저 기준을 잡는 편이 안전하다.

### 4.2 조건에 맞지 않아 제외한 후보

| 모델 | 제외 사유 |
|---|---|
| F5-TTS | 공식 체크포인트가 중국어, 영어뿐. 공개된 한국어 파인튜닝을 찾지 못함 |
| IndexTTS-2 계열 | 지원 언어에 한국어 없음 |
| Zonos | 한국어 미지원 |
| Spark-TTS, MaskGCT | 중국어, 영어만 지원 |
| Supertonic | 한국어는 되지만 고정 프리셋 음성만 제공, 복제 불가 |
| Kokoro | 음성 복제 기능 없음 |
| MeloTTS 단독 | 복제 기능 없음. 음성 변환 앞단의 베이스 TTS로만 쓸 수 있음 |

### 4.3 제로샷과 파인튜닝의 차이

| | 제로샷 | 본인 녹음 파인튜닝 |
|---|---|---|
| 준비물 | 참조 음성 3\~10초 | 녹음 10\~60분과 그 대본 |
| 가져오는 것 | 음색의 전반적인 인상 | 음색, 발음 습관, 말끝 처리, 억양 패턴 |
| 결과의 일관성 | 문장마다 흔들릴 수 있음 | 안정적 |
| 비용 | 없음 | 녹음, 전사 준비, 학습 시간, 과적합 위험 |
| 목소리 교체 | 파일만 바꾸면 됨 | 다시 학습해야 함 |

목소리 하나만 쓰면 되고 녹음을 직접 만들 수 있는 경우라면, 파인튜닝의 단점(교체가 번거로움)은 문제가 되지 않고 장점만 남는다. 이 프로젝트는 녹음을 만들 수 없어서 해당하지 않았다. [판단]

## 5. 추천 경로

5번은 조사 시점(2026-10-08)에 세운 계획이다. 녹음을 직접 만들 수 있다는 전제로 썼는데, 실제로는 녹음을 새로 만들 수 없어서 계획대로 진행하지 못했다. 각 항목이 실제로 어떻게 됐는지는 아래와 같다.

| 항목 | 실제 결과 |
|---|---|
| 5.1 녹음 준비 | 하지 못함. 이후의 파인튜닝 경로가 전부 여기서 막힘 |
| 5.2 현재 TTS 뒤에 RVC | 학습에 약 10분의 녹음이 필요해서 시도하지 못함 |
| 5.3 GPT-SoVITS 파인튜닝 | 파인튜닝은 하지 못하고 10초 참조 음성의 제로샷으로만 측정함. 결과가 기대에 못 미쳐 제거함 |
| 5.4 Qwen3-TTS | 시도하지 않음 |
| 5.5 현재 모델 직접 파인튜닝 | 시도하지 않음 |
| 5.6 진행 방식 | 문장 12개, 참조 음성 3개로 합성 360개를 만들어 측정하고 직접 들어 봄 |

녹음을 10분 이상 준비할 수 있는 경우에는 아래의 순서가 여전히 참고가 된다. 위험이 낮고 시도하기 쉬운 것부터 순서대로 적었고, 앞 단계에서 만족하면 뒤는 하지 않아도 된다.

### 5.1 먼저: 본인 음성 녹음 준비

어느 경로로 가든 필요하다. 조용한 환경에서 평소 말투로 10\~30분을 녹음하고, 문장 단위로 대본을 맞춰 둔다. 이 데이터는 아래 모든 선택지에서 재사용된다.

### 5.2 가장 시도하기 쉬운 실험: 현재 TTS 뒤에 RVC

- 지금 서버 출력을 본인 음성으로 학습한 RVC 모델에 통과시킨다.
- 서버 코드에서는 디코더 출력 뒤에 변환 단계를 하나 추가하면 되고, 클라이언트는 바꿀 것이 없다.
- 현재 모델의 속도(0.13초)를 유지하면서 음색 유사도를 올릴 수 있다.
- 한계: 억양과 말투는 지금 모델 그대로다. "음색은 내 목소리인데 말하는 방식이 다르다"는 느낌이 남을 수 있다.

### 5.3 본격적인 방법: GPT-SoVITS 파인튜닝

- 본인 음성 소량으로 파인튜닝하는 용도에 맞춰 만들어진 도구다.
- 한국어를 공식 지원하고 MIT 라이선스이며, 현재 Docker 이미지와 같은 PyTorch 2.7 / CUDA 12.8 환경에서 테스트된 것으로 조사됐다.
- 속도가 후보 중 가장 여유롭다.
- 약점: 한국어 억양이 어색하다는 커뮤니티 평이 있고, 참조 음성 선택에 결과가 크게 좌우된다고 한다.

### 5.4 대안: Qwen3-TTS

- 한국어 유사도 수치가 공개된 유일한 후보다.
- 스트리밍으로 첫 소리가 빨리 나오므로 체감 지연이 좋을 수 있다. 다만 스트리밍을 살리려면 클라이언트 재생부를 고쳐야 한다.
- 위험: 가속 Fork가 사실상 필요하고, RTX 5070 실측치와 파인튜닝에 필요한 메모리가 문서에 없다.

### 5.5 권하지 않는 길: 현재 모델 직접 파인튜닝

컨테이너 안에 `train_finetune_no_bert.py`가 있는 것은 확인했다. [실측] 하지만 절차 문서가 없고, 원본이 권하는 데이터가 약 1시간이며, 원본 예시는 A100 4장으로 4시간이 걸렸고, 12GB에서는 메모리 부족 위험이 크다. [조사] 같은 노력을 들인다면 5.3이 낫다. [판단]

### 5.6 진행 방식 제안

후보를 한꺼번에 서버에 연결하기 전에, 같은 문장 5\~10개를 각 모델로 합성해 직접 들어 비교하는 것이 먼저다. 유사도는 결국 귀로 판단해야 하고, 공개된 수치는 모델마다 측정 방식이 달라 서로 비교하기 어렵다.

## 6. 모델을 바꿀 때 이 프로젝트에서 고칠 곳

현재 구조는 모델 교체에 유리하다. 클라이언트는 "`/tts`에 JSON을 보내면 WAV가 온다"는 약속만 알고 있다.

| 대상 | 변경 필요 여부 | 내용 |
|---|---|---|
| `server.py`의 모델 로딩과 추론 | 전면 교체 | 현재 코드는 StyleTTS2 전용 |
| `Dockerfile`, `requirements.txt` | 교체 | 새 모델의 의존성과 저장소 |
| `download_model.py` | 수정 | 새 체크포인트 경로 |
| `/tts` 요청, 응답 형식 | 유지 가능 | `text`를 받아 WAV를 돌려주는 형식을 그대로 두면 클라이언트 수정이 최소화됨 |
| `alpha`, `beta`, `diffusion_steps`, `embedding_scale` | 의미 없어짐 | StyleTTS2 고유 파라미터. 새 모델의 파라미터로 바꾸거나 무시 |
| `speed` | 대부분 유지 가능 | 대부분의 모델에 대응 파라미터가 있음 |
| 참조 음성 업로드 | 파인튜닝 방식이면 불필요 | 목소리가 가중치에 들어 있으므로 매 요청마다 올릴 필요가 없어짐. 원격 사용 시 지연도 줄어듦 |
| 클라이언트 설정 창의 튜닝 슬라이더 | 수정 | 서버 파라미터에 맞춰 조정 |
| 클라이언트 재생부 | 스트리밍을 쓸 때만 | 현재는 전체 WAV를 받은 뒤 재생. 스트리밍 모델의 장점을 살리려면 청크 단위 재생으로 변경 필요 |
| 단축키, 오버레이, 장치 선택, 볼륨 | 변경 없음 | 모델과 무관 |

서버 쪽에 "모델 백엔드" 경계를 하나 두면, 여러 모델을 바꿔 가며 비교하기 쉬워진다. 합성 함수 하나(`텍스트 -> 파형`)만 구현하면 되는 형태다.

## 7. 이 프로젝트의 차별점

### 7.1 차별점이 아닌 것

솔직하게 구분해 둔다. 다음은 이 프로젝트만의 것이 아니다.

- **모델과 음성 복제 품질**: 공개된 Fork와 체크포인트를 가져다 쓴 것이다. 품질은 모델에서 오고, 지금은 그 품질이 목표에 못 미친다.
- **자체 호스팅, 무료, 프라이버시**: GPT-SoVITS를 비롯한 4번의 후보 대부분이 같은 성격이다.

예전 README에는 이 프로젝트를 "TTS 엔진"으로서 다른 엔진과 비교하는 표가 있었는데, 그 축에서는 우위를 주장하기 어렵다. 그래서 2026-10-10에 README를 다시 쓰면서 그 표를 삭제했다.

### 7.2 실제 차별점

**"마이크를 쓸 수 없는 사람이, 타이핑으로, 자기 목소리로 보이스챗에 참여하게 해 주는 도구"** 라는 점이다. 공개된 TTS 프로젝트 대부분은 음성을 **만드는** 도구(WebUI에서 파일 생성)이고, 이 프로젝트는 음성으로 **대화하는** 도구다.

| 차별점 | 근거가 되는 구현 |
|---|---|
| 입력에서 송출까지 한 흐름 | 전역 단축키 -> 오버레이 입력 -> 합성 -> 가상 케이블 재생. 다른 창을 떠나지 않고 문장당 키 입력 몇 번 |
| 대화 속도에 맞는 지연 | 첫 요청 이후 0.11\~0.15초 [실측] |
| 게임 환경에 대한 고려 | 저수준 마우스 훅을 사용하지 않고 윈도우의 정식 단축키 기능만 사용함. 화면을 적게 가리는 작은 창과 심플 창 설정 |
| 출력 실수 방지 | 미리듣기는 출력 장치가 아닌 듣기 장치로만 재생. 가상 장치에서도 동작하는 샘플 단위 볼륨 |
| 본인 목소리 전제 | 타인 사칭이 아닌 자기 목소리 복원이 목적. 윤리 고지가 문서에 포함됨 |
| 모델 교체 가능 구조 | 클라이언트와 추론 서버가 HTTP로 분리되어 있어, 더 나은 모델이 나오면 서버만 바꾸면 됨 |
| 디버깅 기록 | `strict=False` 무음 실패, 프레임 시프트, 가상 장치 볼륨 등 실제로 부딪힌 문제와 해결이 [history.md](./history.md)에 남아 있음 |

### 7.3 차별점을 더 뚜렷하게 만드는 방향

현재 구현은 "입력창 하나"에 머물러 있다. 대화 도구라는 정체성을 강화하려면 다음이 효과적이다. [판단]

| 기능 | 이유 |
|---|---|
| 자주 쓰는 문구 단축키 (인사, 대답, 감탄) | 타이핑 없이 즉시 반응. 대화에서 가장 큰 지연은 합성이 아니라 타이핑 |
| 입력 기록과 재전송 | 같은 말을 다시 할 때 |
| 합성 대기열 | 지금은 재생 중에 누른 Enter가 버려짐. 연달아 말할 수 있어야 대화가 끊기지 않음 |
| 재생 중단 단축키 (구현함) | 잘못 보낸 문장을 끊기 |
| 내 스피커로 동시 모니터링 (송출시 듣기로 구현함) | 상대에게 어떻게 들리는지 본인이 확인 |
| 합성 중 상태 표시 | 지금은 요청이 진행 중인지 알 수 없음 |
| 문장 단위 스트리밍 재생 | 긴 문장에서 첫 소리가 빨리 나오게 |
| 본인 목소리 등록 절차 안내 (녹음 -> 학습 -> 적용) | 5번의 파인튜닝을 사용자가 따라 할 수 있게. 이것이 갖춰지면 "내 목소리"라는 핵심 가치가 실제로 전달됨 |

README의 소개 문구는 이 방향으로 바꿨다(2026-10-10). 예전에는 "방송, 스트리밍, 게임 보이스 용도"의 TTS로 소개했는데, 지금은 만든 동기인 **"마이크를 사용할 수 없는 상황에서 말하기"** 를 맨 앞에 두었다.
